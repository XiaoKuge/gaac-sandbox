和比赛有关的几处特性

第一阶段考 KV 状态管理、PD 分离和长任务，下面这几处直接影响怎么搭推理栈。

特性技术报告和 vLLM 博客里怎么写跟哪道考题有关
上下文序列长度在预训练中扩到 1M token；从 4K 到 1M，单 token 解码计算量只增加约四分之一长任务，任务完成时间
全局 KV 缓存跨层共享，用 FP4 存，每 token 约 890 字节I3 KV 状态管理
滑动窗口 KV不压缩，用 FP8 存，覆盖 40 层每层最近 128 个位置；前缀缓存要在每个可能命中的边界存一份I3 前缀复用，I4 PD 分离时的 KV 交接
投机解码自带 DSpark 草稿结构：半自回归生成草稿，按置信度安排验证单流生成速度；正式评测能否开启待定

KV 缓存：模型为已读内容保存的中间结果，复用它可以少算一遍。PD 分离：把读入提示（预填充）和逐字生成（解码）放在不同的卡上。来源：DeepSeek-V4.1-Flash 技术报告；vLLM 博客 2026-10-07、2026-10-23。

开卷和正式评测，用法不一样

第 30 小时封存正式系统，模型、Harness（智能体运行框架）、工具和依赖一起冻结。

开卷，0 到 30 小时

  • 任何模型、智能体、开发与诊断工具都能用，包括 Codex、Claude Code
  • 外部工具的用量和本地资源分开记录
  • 不能用外部资源替代本地底座的验收

封存以后的正式评测

  • 只调用本地部署的 DeepSeek V4.1 Flash 1017
  • 不接在线智能体，不接外部模型接口
  • 每次运行前复位缓存：复位后发一个探针请求，缓存命中 token 为 0 才算复位成功
  • 引擎要开启缓存复位接口，只对评测方的 Runner（自动投题、收卷的程序）网络开放
  • 网络怎么管：待定
